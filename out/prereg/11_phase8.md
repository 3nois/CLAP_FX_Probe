# Phase 8 — 사전 등록 (2026-08-27)

Phase 6이 답한 질문: "예측된 손잡이 방향이 오디오 생성에 반영되는가" → 예, 하지만
축마다 크게 다르고(highshelf +0.0954 최강, lowshelf +0.0325 최약, reverb 하위⅓
+0.0009로 유일한 널) 임베딩 단계(cos 0.71~0.82) 대비 손실이 크다. Phase 8의 질문은
"그 손실을 공학적으로 줄일 수 있는가"다.

이 문서는 실행 전에 세 가지를 한다: (1) 지시서의 수치·공식 중 코드/자료로 직접
검증되지 않은 부분을 감사하고 필요하면 정정한다, (2) A/B/C/D 각각의 예측을 계산
가능한 만큼 계산해서 적는다, (3) 판정 기준을 절대 수치로 못박는다.

## 0. 설계 감사 — 실행 전 정정 5건

지시서의 수치·공식을 코드와 대조한 결과, 실행에 영향을 주는 정정이 5건 나왔다.
전부 "실행 전" 단계에서 잡았다는 점에서 결함 18~21과는 다르다(사후 발견이 아니라
사전 감사) — 별도 결함 번호는 매기지 않고 여기 기록한다.

### 0.1 "잔차 57.4%"는 샘플링 잡음 측정치가 아니다

`docs/round9.md`의 57.4% 잔차는 `phase_f4_full.py`의 이원분산분석(SS 비율)에서
나온 값이며, 그 실험은 **모든 생성 호출에 `GEN_SEED=42`를 고정**해서 돌았다
(`synthesize_from_embedding(..., seed=GEN_SEED, ...)`, 코드 확인). 즉 그 57.4%는
"(소스×이펙트) 조합 - MIDI 변형 주효과"를 뺀 잔차이지, **같은 입력을 다른 시드로
반복 생성했을 때의 변동이 아니다.** 같은 이유로 Phase 6의 41,280건도 전부
`GEN_SEED=42` 고정이라, 축·소스별로 관측된 큰 편차(예: 로그에 찍힌 -0.34~+0.51)는
전부 "소스마다 다른 진짜 신호"이지 시드 잡음이 섞인 것이 아니다 — **이 프로젝트에는
아직 시드 대 시드 변동을 직접 잰 자료가 없다.**

**결론**: 가설 A("잔차 = 샘플링 잡음")를 57.4%에서 역산할 수 없다. 대신 아래 A절에서
두 개의 경계 시나리오로 예측을 등록하고, Phase 8-1이 이 프로젝트 최초의 실제
시드-대-시드 측정이 된다.

### 0.2 pinv는 "과소결정계"가 아니라 "과대결정계"다

`clap_projection`은 `Linear(512,1024) → ReLU → Linear(1024,1024)`(코드로 직접
확인, `embed_dim=1024`). 야코비안 $J = \partial\text{proj}/\partial x$의 shape는
**(1024, 512)**(출력행 × 입력열) — 즉 $J \cdot d_{in} = d_{target}$은 미지수
512개에 방정식 1024개인 **과대결정계**다. 지시서의 "과소결정계, 최소노름 해"는
반대 방향(1024→512 지도를 가정한) 설명이며 이 네트워크에는 안 맞는다.

`pinv(J) @ d_target`(shape 512)은 여전히 맞는 연산이지만, 그 의미는 "여러 해 중
최소노름 해"가 아니라 **"$d_{target}$을 정확히 못 맞출 수도 있는 상황에서의
최소제곱 근사해"**다. $J$가 열계수(column rank) 512로 꽉 차 있으면(하단 8-2 §3에서
특이값으로 확인) 해는 유일하다. 지시서의 위험 문구("과소결정계이므로 최소노름 해가
나온다")는 정정하되, 실질 조치(노름·다양체 이탈 확인)는 그대로 유지한다.

### 0.3 temperature는 MIDI 채널에 적용되지 않는다

`utils.sample()`의 `top_k_sampling`/`top_p_sampling`을 보면 **MIDI 로짓
소프트맥스는 temperature로 나누지 않고, 오디오 9채널 로짓만 나눈다**(코드 40~110행).
따라서 가설 C("온도를 낮추면...")의 효과는 오디오 토큰 샘플링에만 적용되고,
MIDI 채널(생성 중 범위/종료 토큰 예측)은 temperature 무관이다 — 완전한 무작위성
제거가 아니라는 뜻으로, 이 사실 자체를 C의 예측에 반영한다.

### 0.4 `synthesize()`는 temperature 인자를 받지 않는다 — 런타임 몽키패치로 해결

`TokenSynth.synthesize(clap_embedding, midi_fname, top_p=None, top_k=None,
guidance_scale=None)`에는 temperature 인자가 없고, 내부에서 `utils.sample(...)`을
temperature 없이(기본값 1.0) 호출한다. `tokensynth_paper/`는 벤더 미러라 수정하지
않는다. 대신 Phase 8 스크립트에서 **`tokensynth.utils.sample`을 런타임에
몽키패치**해서 원하는 temperature를 주입한다 — `model.py`는 `from tokensynth import
utils`로 모듈을 참조하고 호출 시점에 `utils.sample`을 조회하므로, 파일을 고치지
않고 속성만 바꿔치기하면 된다. 이건 "재구현 금지" 대상(inject.py/midi_gen.py/
phase_f2_filter.py)의 생성 로직을 다시 짜는 게 아니라, 이미 `utils.sample`에
존재하는 temperature 매개변수를 노출만 하는 것이다.

### 0.5 생성 수 재계산 — 3,200 → 4,000 (약 8.5h → 약 10.7h)

지시서의 `100 × 4 × 2 × 4 = 3,200`은 조건 c(미조작 wet)/d(개입) 쌍 구조를 반영하지
않은 수식이다. 실제로 필요한 건:

```
조건 c (e_wet, 미조작)  — α 에 의존하지 않음 → (source, temp, seed)당 1회
조건 d (e_inject(α))    — α 마다 새로 생성    → (source, temp, seed, α)당 1회
```

조건 c는 α축에서 공유(캐싱)할 수 있으므로:

```
c 생성 수 = 100 × 2(온도) × 4(시드)             =   800
d 생성 수 = 100 × 4(α) × 2(온도) × 4(시드)      = 3,200
합계                                            = 4,000
```

Phase 6 실측 처리율 0.104 gen/s 기준 **약 10.7시간**(재현 확인 30분 포함, 순수
그리드는 약 10.2시간). 재현 확인(α=1·기본온도·seed=42)은 이 그리드의 부분집합이라
**낭비 없이 재사용된다** — 별도로 다시 도는 게 아니라 그리드 실행의 첫 조각이다.

## 4. 예측 (실행 전)

### A. k(시드 평균) 의존성

§0.1에 따라 57.4%에서 정밀한 수치를 역산할 수 없다. 대신 **경계가 뚜렷한 두
시나리오**를 등록하고, Phase 8-1이 어느 쪽인지 최초로 직접 답한다.

```
시나리오 A1 "잔차 대부분이 샘플링 잡음"
  k=1→4로 노이즈 표준편차가 1/√4=1/2로 줄면, 현재 da(≈0.089, 84.9°)가
  기하학적으로 절반 가까이 좁혀질 것으로 예측한다 — da가 대략 0.15~0.20
  (78.5~81°) 범위까지 오를 것으로 예측(넓은 사전등록 구간, 정밀도보다 방향성 우선).

시나리오 A2 "잔차가 샘플링이 아니라 구조적 손실(조건화 신호 자체가 약함)"
  k=1→4로 늘려도 da는 k=1의 95%CI 안에 머문다 — 유의한 개선 없음(da 변화폭
  <0.02, 방향도 랜덤).

예측: A1과 A2 중 어느 쪽에 가까울지 사전에 확정하지 않는다(그래서 실험이다).
다만 §0.1에서 확인했듯 이 프로젝트에 시드 잡음의 직접 증거가 없으므로, "잔차의
상당 부분이 소스 고유의 진짜 신호(패밀리·개별 소스 특성)"라는 Phase 6의 관측
(패밀리별 편차가 큼, mallet이 9차에서 부호까지 반전됐던 전례)에 무게를 실어
A2 쪽에 약하게 기운 예측을 등록한다 — 즉 **개선이 있더라도 부분적(0.1~0.15
구간)일 가능성을 A1의 낙관적 시나리오보다 더 유력하게 본다.**
```


### C. temperature 방향

```
예측: 온도를 낮추면(1.0→0.7) da가 오를 것으로 예측한다.
근거: 낮은 온도는 오디오 토큰 샘플링을 모델이 가장 선호하는(로짓이 큰) 토큰
쪽으로 더 확정적으로 몰아준다 — 조건화 신호가 로짓에 실제로 반영돼 있다면,
그 신호를 "잡음에 덜 묻히게" 만드는 효과가 A(시드 평균)와 방향은 같되 메커니즘이
다르다(A는 사후 평균, C는 사전 샤프닝).
단, §0.3 때문에 MIDI 채널은 영향을 안 받으므로 A만큼 크지는 않을 것으로 예측
(A가 유의하다면 C의 개선폭은 A의 절반 이하일 것으로 예측).
위험: 온도를 너무 낮추면 반복·단조로운 토큰 시퀀스로 재구성 충실도 자체가
떨어질 수 있다 — 0.7은 보수적으로 고른 값이라 이 위험은 작을 것으로 예측.
```

### D. 교호작용 (α × temperature)

```
예측: 있다. α를 키울수록(입력이 다양체를 벗어날수록) 자기회귀 샘플링이 그
불안정한 조건을 "얼마나 충실히 따라가는가"가 temperature에 더 민감해질
것이라고 예측한다 — 구체적으로, **낮은 temperature가 α=3~5의 재구성 붕괴를
완화하는 방향으로 작용할 것**으로 예측(사후 확률질량이 소수 토큰에 집중되면
비정상 입력에서도 상대적으로 "안전한"/자주 나오는 토큰을 고르게 되어 붕괴가
누그러질 수 있다는 논리). 즉 da(α)의 역U자 정점이 temperature=0.7에서
temperature=1.0보다 더 오른쪽(더 큰 α)으로 이동할 것으로 예측한다.
```

## 6. Phase 8-2 게이트 — 연산 정의 재정리 (사전 확정)

§0.2에서 정정했듯, 현재 방식(naive, $d_{in}=v=e_{dry}-e_{wet}$)은 **α=1에서
정의상 정확히** $\cos(\text{proj}(e_{inject})-\text{proj}(e_{wet}), d_{target})=1$을
낸다(순환논리 — $d_{target}$ 자체가 그 지점의 proj 차이로 정의되므로). 따라서
"게이트가 통과하는가"를 α=1 단일 지점에서 묻는 것은 무의미하다.

**실제로 의미 있는 비교는 α>1(외삽) 구간에서 두 방향의 감쇠 곡선을 비교하는
것이다:**

```
d_naive(α)  = e_wet + α·v                                (기존, §B와 동일 계열)
d_jac(α)    = e_wet + α·(pinv(J)·d_target을 ‖v‖로 정규화한 벡터)
                                                            (야코비안 정보 사용)

cos_naive(α) = cos(proj(d_naive(α)) − proj(e_wet), d_target)
cos_jac(α)   = cos(proj(d_jac(α))   − proj(e_wet), d_target)

게이트 통과 조건(사전 확정):
  α ∈ {2,3,5} 중 하나 이상에서 cos_jac(α) − cos_naive(α) ≥ 0.05
  (proj 공간에서의 코사인 차이 — 오디오를 만들기 전에 전부 무료로 계산됨)

통과 못 하면(모든 α에서 차이 <0.05) 8-2 오디오 검증은 생략하고 "야코비안
정보가 이 스케일에서 추가 이득이 없다"로 기록, Phase 8 종합 판단에는 8-1
결과만 반영한다.
```

$J$(1024×512)의 열계수 확인: 특이값 분해로 최소 특이값을 100개 소스 각각에서
보고하고, 0에 근접(예: 최대 특이값의 1e-3 미만)하는 소스가 있으면 그 소스는
pinv 해를 신뢰하지 않는다고 별도 표시한다.

$d_{jac}$의 노름·방향이 §3의 다양체 이탈 기준(코사인/노름)을 벗어나면 경고
문구를 표에 남긴다(지시서 원문의 취지 유지).
